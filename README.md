# 🍪 KUS — облік для бренду печива

Бюджетна система «як Poster» для цеху печива: каса, замовлення, техкарти з автоматичною собівартістю, склад, клієнти й опт, гроші, звіти, аналітика, персонал, етикетки, фіскальні чеки та AI-помічник на базі Claude.

**Сайт:** https://edtjnfnjhfd.github.io/KUS-business-/ (оновлюється автоматично після кожного пуша)

## Розділи

### Продажі
| | |
|---|---|
| **🧾 Каса** | Товари плиткою, пошук і категорії. Клієнт у чеку (пошук за ім’ям/телефоном, швидке створення), персональна знижка, **оптові ціни** для оптовиків, знижка в ₴ або %, **бонуси** (кешбек), оплата на будь-який рахунок або **в борг**, канал продажу (Instagram, маркет…), фіскальний чек, друк чеку, «Оформити як замовлення». На ПК: `/` — пошук, `Ctrl+Enter` — оплатити. |
| **📦 Замовлення** | Передзамовлення: клієнт, дата й час видачі, самовивіз/доставка, **передоплата** (з рахунком), статуси Нове → Підтверджене → Готується → Готове → Видане. «Видати» створює продаж з урахуванням передоплати. |
| **🚗 Транспорт** | Витрати на таксі, водія, пальне, пошту (можна прив’язати до замовлення кнопкою «🚗 Поїздка»). Порівняння: скільки клієнти заплатили за доставку vs скільки пішло на транспорт → чи окупається доставка. Ціна доставки для клієнта (за замовчуванням 50 ₴) — окремим рядком чеку, не змішується з виручкою від печива. |
| **🧮 Чеки** | Історія з пошуком, редагування, **повернення**, друк чеку (58 мм) і **накладної** (А4), фіскалізація заднім числом. |
| **🕐 Касові зміни** | Відкриття з сумою в касі, внесення/вилучення, закриття з підрахунком готівки — програма показує нестачу/надлишок. Звіт у Telegram, Z-звіт у Checkbox. |

### Виробництво
| | |
|---|---|
| **🥣 План випічки** | Беремо замовлення на дату + скільки треба на вітрину → скільки **замісів** якої техкарти, які інгредієнти потрібні, **чого не вистачає** на складі і **список покупок** (копіюється одним натиском). Друк плану. |
| **📋 Техкарти** | Склад, вихід, втрати, пакування «на 1 шт», дод. витрати, набори з інших техкарт. Собівартість, маржа, націнка, food cost, рекомендована ціна, **оптова ціна**. |
| **🏷️ Етикетки** | Склад (автоматично за спаданням маси), алергени, маса, дата виготовлення, «вжити до», умови зберігання, виробник. Термо 58×40 / 40×30 або А4. |

### Склад
| | |
|---|---|
| **🏬 Залишки** | Поточні залишки (постачання − продажі за техкартами ± інвентаризації), мінімальні залишки, «Докупити», вартість складу, історія руху. |
| **🚚 Постачання** | Закупівлі: додають залишки, оновлюють ціни (→ собівартість), списують гроші з рахунку. Чек можна внести через AI. |
| **⚖️ Інвентаризація** | Звірка факту з програмою (нестачі в ₴) і **списання** (зіпсоване, брак, дегустація) — і інгредієнтів, і готової продукції. |
| **🧈 Інгредієнти** | Ціни, історія цін, де використовується. |

### Клієнти, фінанси, команда
| | |
|---|---|
| **👥 Клієнти та опт** | База з історією покупок, сумою, середнім чеком, бонусами, **боргами** (і погашенням), днями народження. Оптові клієнти отримують оптові ціни. |
| **📊 Звіти** | Виручка, собівартість, валовий і **чистий** прибуток (мінус витрати, зарплата, списання), порівняння з попереднім періодом ▲▼, графік, топ товарів. |
| **📈 Аналітика** | **ABC-аналіз** меню, продажі по днях тижня і годинах, канали, категорії, працівники. |
| **💳 Гроші й рахунки** | Каса / термінал / рахунок ФОП: залишки й увесь рух грошей, перекази, інкасація. |
| **💸 Витрати** | Оренда, реклама тощо — з рахунку, з якого платили. |
| **💼 Персонал і зарплата** | Працівники з ролями (власник, менеджер, касир, пекар), **вхід за PIN**, касир не бачить собівартість і прибуток. Зарплата: ставка за зміну + % від продажів, виплати. |

### Інтеграції
| | |
|---|---|
| **☁︎ Синхронізація (Supabase)** | Однакові дані на телефоні, ПК і в працівників. Зміни зливаються по записах — нічого не губиться, навіть якщо два пристрої працювали офлайн. Безкоштовно. Налаштування → Синхронізація (покрокова інструкція і SQL там же). |
| **ПРРО Checkbox** | Фіскальні чеки з каси (готівка/безготівка, знижки, повернення), відкриття/закриття фіскальної зміни. Спершу — тестова каса. |
| **Telegram** | Звіт при закритті зміни і щоденний звіт за вчора: виручка, прибуток, топ, що закінчується, замовлення на завтра. |
| **✨ AI (Claude)** | Чек/фото → постачання з цінами, середні ціни в регіоні з інтернету, рецепт → техкарта, аналітик по ваших цифрах. |

## Як працює собівартість і склад
- Ціна інгредієнта — з останнього постачання (або вручну). Змінилася ціна → техкарти перераховуються.
- При продажу **фіксується собівартість і списання складу** на цей момент — старі звіти не «пливуть».
- Залишок = постачання − продане (за техкартою, з втратами) ± інвентаризації/списання.

## Запуск
- **Сайт:** https://edtjnfnjhfd.github.io/KUS-business-/ → у браузері «Додати на головний екран».
- **Файлом:** [`release/KUS.html`](release/KUS.html) — відкрити в браузері.
- **Розробка:**
  ```bash
  npm install
  npm run dev       # локальний сервер
  npm test          # тести (розрахунки, склад, гроші, синхронізація, Checkbox, Telegram, AI)
  npm run release   # зібрати release/KUS.html
  ```

## Дані й безпека
- Без синхронізації дані лежать у браузері пристрою — робіть **резервну копію** (Налаштування → Дані).
- API-ключ Claude і доступ до Supabase зберігаються лише на конкретному пристрої та не потрапляють у резервні копії чи синхронізацію.
- Ключ Checkbox і токен Telegram синхронізуються між пристроями бізнесу (щоб каса на будь-якому пристрої могла видати чек).
- PIN-коди захищають від випадкового доступу на спільному пристрої, але це не банківський рівень захисту.

```
src/calc.js        — уся математика: собівартість, склад, план випічки, гроші, клієнти, ABC, зарплата
src/store.js       — стан, позначки змін для синхронізації, злиття, демо-дані, міграції
src/checkout.js    — створення продажу/повернення (собівартість, списання, бонуси)
src/sync.js        — синхронізація через Supabase
src/fiscal.js      — ПРРО Checkbox
src/telegram.js    — звіти в Telegram
src/ai.js          — Claude: чеки, рецепти, пошук цін, аналітик
src/nav.js         — розділи меню і права ролей
src/pages/*.jsx    — екрани
tests/             — node:test
```
